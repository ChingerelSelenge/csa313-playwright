## Хийсэн ажил

Энэ репозиторид [www.saucedemo.com](https://www.saucedemo.com) дэлгүүрийн нэвтрэх болон худалдан авалтын функцийг Playwright-ээр автоматжуулсан 3 тест байна:

1. **Амжилттай нэвтрэх** — зөв хэрэглэгчийн нэр, нууц үгээр нэвтэрч, Products хуудас гарч ирснийг шалгасан.
2. **Амжилтгүй нэвтрэх** — буруу нууц үгээр нэвтрэхэд алдааны мессеж гарч байгааг шалгасан.
3. **Бараа сагслах** — нэвтэрсний дараа нэг бараа сагслаж, сагсны тоо 1 болсныг шалгасан.

Тест бүр `getByRole`, `getByPlaceholder` зэрэг орчин үеийн locator ашигласан бөгөөд нэвтэрсэн тест бүр logout хийж, URL-ээ шалгаж дуусдаг.

`tests/mytest.spec.ts` файлд тестийн код, коммент бүхий байгаа.

## Playwright vs Selenium 

Playwright болон Selenium хоёулаа UI автомат тест хийхэд ашиглагддаг. Миний туршилтаар Playwright-ийн locator ашиглах хэлбэр нь илүү ойлгомжтой санагдсан. Playwright нь элемент бэлэн болохыг автоматаар хүлээдэг тул олон тохиолдолд гараар wait бичих шаардлагагүй. Мөн browser-уудыг нэг командаар суулгаж ашиглах боломжтой нь тохиромжтой байлаа. Playwright-ийн Codegen нь browser дээр хийсэн үйлдлээс код үүсгэж өгдөг. Trace Viewer ашигласнаар тестийн алдааг алхам бүрээр нь шалгах боломжтой байсан. Selenium-д мөн олон төрлийн хэл дэмждэг давуу тал байдаг. Гэхдээ энэ лабораторийн хүрээнд Playwright-ийн auto-wait, Codegen болон Trace Viewer нь илүү тохиромжтой санагдсан.

## Codegen туршилт

`npx playwright codegen saucedemo.com` командаар автоматаар үүсгүүлсэн код `docs/codegen.ts`-д хадгалагдсан.

Codegen ашиглах үед Playwright миний хийсэн үйлдлүүдийг автоматаар
locator болон action болгон хувиргаж өгсөн. Миний гараар бичсэн код
илүү цэгцтэй бөгөөд assertion-уудыг өөрөө тодорхойлсон. Харин Codegen ихэвчлэн үйлдлийг бүртгэхэд төвлөрч, тестийн зорилгыг өөрөө ойлгож assertion үүсгэдэггүй. Мөн Codegen-ээс гарсан зарим locator-ыг илүү тогтвортой locator болгон өөрчлөх шаардлагатай байсан.

## Trace viewer — санаатай унагасан тест

Алхам 4-ийн дагуу assertion-оо санаатай буруу болгож тестээ унагаад, `npx playwright show-trace`-ээр алдааг мөшгөсөн. Уг trace файл `docs/failed-trace.zip`-д хадгалагдсан (ажлын эцсийн хувилбарт бүх тест дахин ЗӨВ болгосон тул `npx playwright test` ажиллуулахад бүгд ногоон гарна).

Би Products текстийг буруу утгаар шалгаж тестийг санаатайгаар
унагасан. Trace Viewer ашиглан тестийн алхмуудыг дарааллаар нь
харж, assertion дээр алдаа гарсныг тодорхойлсон. Screenshot болон
DOM snapshot-оор тухайн үед хуудас ямар төлөвтэй байсныг шалгаж
болсон. Алдааг зассаны дараа тестүүдийг дахин ажиллуулж бүгд
амжилттай болсон.

## Яагаад XPatch-аас зайлсхийсэн

XPath нь DOM-ийн бүтцээс их хамааралтай байдаг тул вебийн бүтэц
өөрчлөгдөхөд тест эвдрэх эрсдэлтэй. Playwright-ийн getByRole,
getByLabel, getByText зэрэг locator-ууд хэрэглэгчийн харж буй
элемент болон accessibility мэдээлэлд тулгуурладаг. Тиймээс
миний тестүүдэд XPath-аас илүү эдгээр locator-уудыг ашигласан.
